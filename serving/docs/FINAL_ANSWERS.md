# 완성 답변의 2초 시간 예산

`answer_academic_question`은 근거 조회부터 최종 문장 생성과 출처 연결까지 서버에서 수행하는 선택 도구다. `ANSWER_BASE_URL`과 `ANSWER_MODEL`이 모두 설정된 경우에만 등록한다. 백필 파일, Retriever와 모델 구현은 변경하지 않는다. 기존 검색 도구도 그대로 유지한다.

## 출력과 시간의 의미

- `status=answered`: `answer`에 완성 문장, `citations`에 서버가 연결한 원문 URL이 있다.
- `display_verbatim=true`: 별도의 LLM 재작성 없이 해당 문장과 출처를 표시하는 클라이언트를 위한 힌트다. 일반 MCP 클라이언트가 이 힌트를 따라야 한다는 보장은 없다.
- `insufficient_evidence`, `login_required`, `needs_clarification`, `out_of_scope`는 실제 답변을 제공한 경우와 구분한다.
- `answer_timeout`: 시간 내 생성 실패다. `answer=null`이며 완성 답변 또는 빠른 정답으로 집계하지 않는다. 짧은 오류 메시지 반환만으로 목표를 달성했다고 평가하지 않는다.

기본 서버 시간 예산은 1.85초로, 검색, 캐시 조회, 실행 대기, 답변 생성, revision 확인과 결과 캐시 기록을 모두 포함한다. 네트워크 및 직렬화 여유를 고려한 값이며 2초 외부 왕복 SLA를 보장하지 않는다. 요청을 받기 전의 네트워크 시간, MCP 초기 연결, 클라이언트가 다시 작성하는 시간은 서버에서 제어할 수 없다. API 생성이 이미 시작된 뒤 취소되어도 공급자의 작업이 즉시 멈춘다고 보장하지 않는다.

## 생성 경로

같은 원문을 사용하고 답변에 필요한 조건과 예외를 보존하면서 질문 핵심만 1~2문장으로 생성하도록 요청한다. 긴 URL을 모델이 다시 출력하는 토큰 비용을 줄이기 위해 JSON에 짧은 원문 번호만 받는다. 자유 문장 프로토콜은 빠른 모델에서 형식 누락이 발견되어 생성 API의 엄격한 JSON Schema 응답 형식을 사용한다. 서버가 번호를 검증하고 실제 검색 결과의 URL을 연결한다. 답변 모델 자체는 `ANSWER_MODEL`로 명시한다. 임베딩과 리랭커 모델은 기존 설정을 따른다.

마무리되지 않은 생성(`finish_reason != stop`), 잘못된 번호, 출처 없는 긍정 답변, 형식 오류는 성공으로 반환하거나 캐시하지 않는다. 이 검사는 인용의 형식과 범위를 확인할 뿐, 모델의 의미적 정확성을 보증하는 사실 검증기는 아니다.

완성 답변 캐시는 검색 캐시와 별도 네임스페이스를 사용한다. 원 질문, 모델/endpoint/프롬프트/토큰 설정, 학기, 대상, 데이터 revision, 기준일 및 기존 대화 분리 정책을 반영한다. 캐시와 진행 중 생성 작업을 공유해 같은 공개 질문을 여러 사용자가 다시 생성하지 않도록 한다. 원래 검색 슬롯을 함께 사용하여 검색과 생성 경로의 총 실행 수를 제한한다.

생성 중 자료가 바뀌거나 모든 호출자가 떠나거나 시간이 초과되면 최종 답변을 캐시하지 않는다. 같은 작업의 호출자 한 명이 취소되어도 남은 호출자의 결과는 유지한다. warm 답변도 현재 revision을 확인한다.

## 설정

```
ANSWER_BASE_URL=<private OpenAI-compatible v1 API base>
ANSWER_MODEL=<explicit model ID>
ANSWER_API_KEY=<private secret>
ANSWER_BUDGET_SECONDS=1.85
ANSWER_MAX_TOKENS=512
```

실제 endpoint와 인증키는 Git 밖 환경 파일에 저장한다. 더 큰 토큰 예산이나 복잡한 질문은 시간 내 완료율을 낮출 수 있다. 2초 예산 때문에 필요한 사실을 누락하거나 시간 초과를 정답으로 처리하지 않는다. 이 도구를 기존 일반 클라이언트에 추가하는 것만으로 화면의 최종 답변까지 2초가 보장되지는 않는다.

## 재작성 없는 터미널 클라이언트

`academic-answer "이중전공 신청 자격은?" --url http://127.0.0.1:8000/mcp` 또는 `python -m academic_mcp.answer_cli`를 사용한다. 서버의 완성 문장과 출처를 바로 출력하고 추가 LLM을 호출하지 않는다. Bearer 키는 `MCP_AUTH_TOKEN` 또는 `MCP_TEAM_TOKEN` 환경변수로 전달하며 명령줄에 키를 넣지 않는다. `--json`은 기계 판독용이다. CLI의 표시 지연은 MCP 초기 연결이 완료된 뒤부터 측정하며 프로세스 시작 시간이나 연결 시간까지 포함한 값으로 오해하지 않는다.

## 원문 항목 직행

`direct_answer.py`는 주제와 이름 있는 필드가 일치하는 경우에만 최대 1,200자의 원문 항목 전체를 최종 안내로 표시한다. 수치, 수수료, 학년 구분, 자격, 신청 방법, 재발급, 반환 기준과 긴 필드 이름의 일치를 사용한다. 생성 결과가 아니므로 `answer_mode=source_item`과 실제 청크 ID를 반환한다.

검색 순위는 바꾸지 않으며, 숫자를 새로 계산하거나 답변을 하드코딩하지 않는다. 특정 대상 문서와 일반 문서를 구분하도록 제목의 마지막 주제를 확인하고, 학점 등 필드 단어만 겹치는 것은 주제 일치로 보지 않는다. 여러 필드를 섞어 묻거나 요청 연도가 원문에 없으면 직행하지 않는다. 제목/필드 판별은 제한된 규칙이므로 미공개 질문에서의 정확성을 보장하지 않는다.

`ANSWER_REASONING_EFFORT`는 해당 API가 지원할 때만 low/medium/high 중 하나를 지정한다. 이 값과 엄격한 JSON Schema 정책도 캐시 키에 반영한다. 형식 오류는 원래 자료를 그대로 사용해 시간 예산 안에서 한 번만 복구한다. 명시적 답변 보류는 정해진 확인 불가 문장으로 표시하며, 누락되거나 잘못된 사실을 만들어 채우지 않는다. 보류는 정답으로 집계하지 않는다.

최종 미리보기는 백필과 임베딩/리랭커를 유지한 GPT-OSS-120B low 설정이다. 로컬에서의 빠른 응답과 별개로 일부 오답, 조건 누락, 불필요한 보류와 시간 초과가 남는다. 기존 운영 서버의 모델을 자동 전환하지 않았으며, 운영 환경 성능과 별도 정답 검토 없이 모든 최종 답변 2초를 보장한다고 주장하지 않는다.

## 단계별 지연과 정확한 필드 조회 (2026-11-27)

두 검색/답변 도구의 `metrics.stage_elapsed_ms`는 요청별 시간을 밀리초로 반환한다. `revision`, `cache_lookup`, `work_wait`, `retrieval`, `embedding`, `rerank`, `generation`, `rewrite`, `answer_routing`, `cache_write`를 구분한다. `queue_ms`는 입장 대기 시간이다. 시간 초과에는 진행 중 HTTP 시간까지 응답 시점의 스냅샷으로 담고 `stage_timings_complete=false`를 표시한다. 이후 작업이 끝나도 이미 반환한 값은 바뀌지 않는다.

시간은 중첩 구간이다(`stage_timing_scope=inclusive_nested_request_spans`). `retrieval`에는 임베딩/리랭킹이, `answer_routing`에는 생성이, `work_wait`에는 작업과 대기가 포함된다. 이 숫자를 합해서 총시간으로 사용하면 안 된다. 실제 총시간은 `server_elapsed_ms`다. 공유 요청의 자체 모델 시간은 0이고 `work_wait`로 공유 작업 대기를 표시한다. 캐시 응답은 이전 요청의 생성 시간을 재사용하지 않는다. 답변에는 설정한 `answer_model`과 기존 배포 버전도 포함한다. 운영 telemetry에는 시간/모델명만 저장하며 질문과 원문은 저장하지 않는다.

`literal_route.py`는 공개 문서의 이름과 필드를 명시한 질문을 스냅샷에서 직접 조회한다. 예: `이중전공 신청자격 알려줘`. 문서/필드가 유일하고 질문 전체가 허용 문법에 맞아야 한다. 정의와 평가요소의 동시 조회는 같은 문서의 두 항목이 모두 있을 때만 가능하다. 특별휴학 사유별 서류/기간은 공식 목록의 해당 항목과 하위 조건 전체를 인용한다. 모호한 문서, 개인 조건, 연도, 학기/대상 인자, 추가 요구가 있으면 일반 검색으로 넘어간다. 데이터 revision을 조회 전후 확인하고 정책을 답변 캐시 키에 포함한다. 이 경로는 `source_item`/`source_items`와 실제 청크 ID를 반환하며 모델을 호출하지 않는다. 임베딩/리랭커 구현이나 검색 순위는 변경하지 않는다.

생성 HTTP 연결의 재사용 기간은 60초이며 동시 연결은 8개로 제한한다. 프롬프트 축약은 실험에서 답변 판단 회귀가 있어 반영하지 않았다. 생성 모델 후보 비교에서도 응답 속도뿐 아니라 보류/오답 위험을 함께 검토한다. 서버 1.85초 예산과 별개로 공개 HTTPS 왕복 및 AI 클라이언트의 추가 문장 생성까지 항상 2초를 보장하지 않는다.

## 모델 호출 없는 최종 답변 재사용 (2026-11-27)

`answer_aliases.py`는 존댓말/명시적 요청 어미와 문장 끝 마침표를 정규화한다. 소수점, 성적의 +, 숫자, 날짜 구분자, 부정은 보존한다. 이 정책과 모델/프롬프트/조회 정책은 답변 캐시 키에 포함된다.

질문 별칭은 전체 질문을 해석하는 제한된 문법이 같은 주제와 요청 필드임을 확인한 경우만 만든다. 예를 들어 복학 신청 위치의 두 표현을 같은 의도로 분류한다. 키워드, SimHash 거리, 임베딩 유사도만으로 최종 답변을 재사용하지 않는다. 문법의 미해석 부분은 주제 슬롯에 그대로 남고, 여러 해석이 경합하면 별칭을 만들지 않는다. 별칭은 성공한 answered/can_answer=true 원본 캐시의 직접 포인터다. 원본과 같은 만료 시각, revision, history, top_k, semester, target, 날짜/모델/검색 profile을 사용한다. 원본 삭제/만료 시 miss, alias→alias 연결과 조회 시 수명 연장은 없다. 같은 검증 의도의 서로 다른 표현도 진행 중 작업을 공유한다. 여기서 검증은 제한된 의도 문법의 동등성 검사이며, 생성 답변의 사실 정확성 인증은 아니다.

같은 의도 문법으로 공식 항목 직접 조회도 확대했다. 원문에 있는 자격, 신청 경로, 휴학기간, 학점 제한, 재수강 성적, 졸업요건을 문서/항목이 유일할 때만 전체 인용한다. 문서 ID가 없거나 바뀌거나 항목이 크거나 모호하면 기존 검색으로 넘어간다. 수치/규정 값은 코드에 넣지 않으며 원문에 없는 개인 결론은 만들지 않는다.

`metrics.model_free_response`는 공유 작업을 포함한 실제 모델 HTTP 시도가 0이고 작업 계수가 완료됐을 때만 true다. shared caller의 자기 호출만 0인 것을 무호출로 표시하지 않는다. timeout은 null이다. `answer_cache_kind=verified_alias`로 최종 답변 별칭 적중을 구분한다.

## 시간초과 원인별 대응 (2026-11-27)

모델 요청의 `http_elapsed_ms`는 connect_tcp/tls/send_headers/send_body/wait_headers/read_body를 분리한다. `wait_headers`에는 원격 처리와 네트워크 시간이 함께 들어 있으므로 순수 NPU 추론 시간으로 부르지 않는다. `http_connections`는 새 TCP 연결 시도 수, `http_bytes`는 POST 송수신 길이다. trace의 URL/헤더/본문은 저장하지 않는다. 성공·timeout 응답 모두 요청 시점 스냅샷이며 공유 caller의 모델 통신을 자기 통신으로 복제하지 않는다.

HTTPX의 단계별 timeout에는 매 HTTP 단계 시작 시 남은 전체 Budget을 다시 적용한다. 연결/업로드가 쓴 시간을 read timeout에서 빼며, 취소된 caller의 후속 단계를 중단한다. 모델 모듈을 수정하지 않고 serving의 검색 클라이언트 풀을60초/최대8개로 관리한다. 기존 환경 프록시/TLS 처리는 유지한다. 생성 클라이언트가45초 이상 유휴였을 때에는 검색 중 한 번의 GET models를 겹쳐 연결을 준비한다. 대기하지 않고, 최대 worker1개/동시1회/45초 cooldown, 정상 생성 중에는 추가 요청을 보내지 않는다. 이 읽기 전용 카탈로그 요청은 임베딩/리랭킹/생성 추론 POST가 아니며 model_calls에 넣지 않는다. `connection_warmup`은 겹치는 보조 구간이며 진행 중이면 stage_timings_complete=false/connection_warmup_pending=true다.

유일한 공식 정책 항목/표는 `policy_fields.py`에서 직접 조회한다. 표의 성적/학점 키를 정확히 확인하고, 과거 학기 길이를 현재 운영 기간으로 오인하지 않는다. 조건·예외·시행일·필요서류가 나뉘면 필수 항목을 모두 묶고 하나라도 빠지면 기존 검색으로 넘어간다. 일반 질병휴학에 첫학기 전용 서류를 적용하지 않는다. 수치/규정은 코드가 아닌 현재 snapshot에서만 가져온다. 이 제한된 문법 밖의 질문은 기존 모델 검색과 생성에 맡긴다.

완성·검증된 답변의 최종 캐시 저장은 선택 사항이다. 남은 시간이30ms 미만이거나 쓰기 잠금이10ms 내에 풀리지 않으면 저장을 건너뛴다. 원본 revision의 마지막 검증은 계속 수행하며, 늦은 응답이나 바뀐 데이터는 성공으로 처리하지 않는다. `cache_write_status`는 stored/hit/budget_skipped/busy_skipped다. 필수 데이터 읽기나 모델 실패를 캐시 문제로 숨기지 않는다. 상위 전체1.85초 예산과 외부2초 목표는 유지한다.

생성 HTTP 전송이 실패해 연결을 재사용할 수 없으면 다음 검색 중 연결 준비를 다시 허용한다. 복구용 카탈로그 읽기는 최대 2초에 한 번, 동시에 한 개로 제한한다. 답변 생성 자체를 재시도하거나 실패 답변을 캐시하지 않는다.
