# 의미 기반 검색 캐시

정확 일치 응답/검색 순위 캐시가 빗나가면 질문 임베딩으로 기존 질문의 검색 근거를 재사용한다. 답변 문장을 의미 유사도만으로 재사용하지 않는다. 백필과 모델 담당자의 retrieval.py 및 색인은 변경하지 않는다.

## 경로

1. 기존 응답 캐시와 정확 일치 순위 캐시를 먼저 확인한다. 적중하면 API 호출이 없다.
2. 인식 가능한 주제와 질문 의도에 한해 기존 Retriever.embed로 질문을 임베딩한다.
3. 주제, 의도, 숫자, 단위, 비교 조건, 성적 문자, 학교/학과, 대상, 부정 표현과 명시적인 semester/target가 같은 버킷만 조회한다. revision, 프로필, 기준일과 후보 범위도 같아야 한다.
4. 기본 코사인 유사도 0.94 이상인 후보를 선택한다. 가까운 후보가 다른 1위 근거를 가리키면 차이 0.02 미만에서 재사용을 거절한다.
5. 적중 시 모델 호출은 질문 임베딩 1회이며, 리랭킹은 생략한다. 응답은 현재 질문으로 다시 조립하고 최신성을 다시 확인한다. 점수는 현재 질문에 대한 새 평가가 아니므로 score_type을 cached_reranker/cached_dense_cosine으로 표시하고 semantic_cache.score_origin=cached_query를 반환한다.
6. 미적중 시 같은 임베딩을 요청별 Retriever 사본에 전달한다. 원래 검색 함수를 그대로 실행하므로 임베딩을 중복 호출하지 않는다. 벡터 인덱스와 HTTP 연결은 공유하고 질문별 임베딩만 분리한다.

## 보존과 제한

- 새로 실제 검색한 결과만 의미 캐시의 출처가 된다. 재사용한 결과를 다시 의미 후보로 등록하지 않아 연쇄적인 의미 이탈을 막는다.
- 유사 질문의 정확 일치 별칭과 응답 캐시 만료는 출처의 만료를 넘기지 않는다. revision 변경 시 발행하지 않는다.
- 기존 SQLite cache 테이블에 semantic: 네임스페이스를 사용한다. 전체 캐시 최대 1000개와 만료 정리를 공유하며, 버킷별 최신 후보 최대128개만 읽는다. 분산 잠금은 없다.
- 기존 모델의 근거 충분성 임계값이 설정되면 의미 캐시를 사용하지 않는다. 다른 질문의 점수로 임계값을 판정하지 않는다.
- 기존 모델 실패를 빈 결과로 바꾸지 않는다. 임베딩 실패, 잘못된 응답, 시간 예산 및 취소 처리는 기존 정책을 따른다.

## 설정과 관측

compose/build_service 기본은 SERVING_SEMANTIC_CACHE=true, SERVING_SEMANTIC_THRESHOLD=0.94다. false로 끌 수 있고 프로필에 포함되어 이전 응답 캐시와 분리된다. AcademicService 직접 생성 시는 기존 호출자 호환을 위해 기본 false다.

request 지표 semantic_cache_hit와 semantic_similarity(응답의 수치), 집계 semantic_cache_hit_rate 및 시계열 semantic_cache_rate를 추가했다. 일반/실험 트래픽은 기존 표식으로 구분한다. 질문 원문이나 임베딩은 telemetry에 추가 기록하지 않는다. 의미 캐시의 후보 임베딩은 학사 캐시 DB에만 보관한다.

## 해석

이는 근사 캐시다. 조건 검사는 인식 규칙에 한정되므로 모든 표현의 의미 동등성이나 오적중 0을 보장하지 않는다. 안전을 위해 인식 불가 주제/의도, 조건 차이, 낮은 유사도, 후보 모호성에서는 일반 검색한다. 알려진 조건 검사의 누락은 추가 평가로 찾아야 한다.

개발 평가셋은 기존64문항, 질문별 수작업 변형2개다. 독립 사람의 의미 동등성 검토는 받지 않았다. 범위 밖12문항을 포함하고, 검색 캐시 적중을 정답 판정으로 해석하지 않는다. source conflict가 알려진 a45를 제외한 초안 근거 라벨로 회귀만 점검한다. 별도 실제 API 조건 변경20쌍과 단위/상한/하한 단위 테스트를 함께 수행한다. 통제된 반복 적중률은 자연 사용자 적중률이 아니다.
