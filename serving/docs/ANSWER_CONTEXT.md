# 서빙 캐시와 일정 직행, 실험용 근거 구성

다른 사용자 간 독립 질문 캐시 공유와 명시 학기 일정 직행은 기본 활성화한다. 아래 근거 구성 기능은 64문항 검증에서 완전 답변이 기존 41개에서 40개로 줄어 기본 비활성화했다. 개발 환경의 `SERVING_ANSWER_CONTEXT=true` 또는 생성자 `answer_context=True`로만 시험한다. 품질 개선이 확인되기 전 운영 기본값으로 바꾸지 않는다.


서빙이 검색 모듈을 호출한 뒤 `answer_context`를 구성한다. 원래 `evidence`, 순위, 점수, status는 유지한다. 모델 코드, 임계값과 백필 파일은 변경하지 않는다.

클라이언트는 `answer_context.sources`를 답변 근거로 사용하고 `guidance`를 확인한다. 각 문서의 제목은 적용 범위이며, 절의 예외와 조건을 보존해야 한다. 수집일은 규정의 시행일이나 최신성 검증일이 아니다. 문서끼리 상충하면 서빙이 어느 쪽이 맞는지 임의 판정하지 않는다.

구성은 다음과 같다.

- 문서 ID, URL, 제목이 모두 같은 청크를 한 문서로 묶는다. ID만 같고 대상 또는 URL이 다르면 합치지 않는다.
- 질문에 문서 제목이 직접 등장하거나 제목의 단어와 겹치면 해당 문서를 먼저 제시한다. 모델의 원래 검색 순위는 `evidence`에서 확인할 수 있다.
- 같은 스냅샷의 동일 문서에서 질문이 명시적으로 요구한 절차, 서류, 자격에 대응하는 절만 보완한다. 단순 주제 유사성으로 다른 과정이나 추가 조건을 붙이지 않는다. 다른 문서에서 임의로 가져와 같은 근거로 합치지 않는다.
- 검색된 원문 절을 먼저 보존하고 문서당 보완 절을 최대 2개 추가한다. 문서당 최대 7개 절, 본문 전체 6,500자로 제한한다. 절과 표를 중간에서 잘라 조건을 누락시키지 않고, 제외된 청크 ID를 `omitted_chunk_ids`에 남긴다.
- 모든 추가 근거는 `supplemental_chunk_ids`와 원문 URL로 추적한다. 서빙이 새 사실이나 정답 문장을 생성하지 않는다.

정확한 학기가 주어지고 날짜만 묻는 경우에는 수집된 일정에서 대상 학기와 행사명이 맞는 항목을 먼저 찾는다. 일치하면 `structured_calendar` 경로로 모델 호출 없이 반환한다. 질문에 자격, 방법, 비용 등의 조건이 섞이거나, 명시 학기와 인자가 충돌하거나, 일치 일정이 없으면 기존 검색을 수행한다. 학기가 없는 질문에 오래된 일정을 현재 일정처럼 붙이지 않는다. `semester`는 일정표 학기, `target_semester`는 행사의 대상 학기다.

기존 캐시, 요청 병합, 실행/대기열 제한, 시간 예산, 스냅샷 revision 재검증은 유지한다. 캐시 키에는 근거 구성 정책 버전, 일정 경로 버전과 지침 해시가 포함되어 예전 응답을 재사용하지 않는다. 모델 설정, 학기, 대상과 revision이 다른 요청은 분리한다. 현재 Retriever는 대화 이력을 읽지 않고 독립 질문만 처리하므로, 이 모드에 한해 같은 질문을 서로 다른 대화에서도 공유한다. 대화 재작성 모델을 쓰는 legacy 모드는 대화 전체로 계속 분리한다. 유사도 기반 공유는 하지 않는다.

## 검증 범위

`test_answer_context.py`는 조건과 표의 보존, 예산 초과 표시, 동일 문서의 관련 절 보완, 대상/URL 분리, 원본 점수 유지, 캐시 오염 방지, revision 변경과 일정 경로의 모델 호출 생략을 검사한다.

기존 64문항은 개선 전후 회귀 평가용이다. 모델/백필을 고정한 통제 실험이며, 이 질문을 보면서 구현했으므로 별도의 미공개 질문셋 검증을 대체하지 않는다. 로컬 실제 모델 API 평가 결과는 공개 저장소 밖에 저장한다.

## 2초 목표의 의미

MCP 도구 반환 시간과 클라이언트 답변 생성 완료 시간은 별도로 측정한다. 서빙이 클라이언트 LLM의 생성 시간을 제한할 수는 없다. 근거를 덜 반환하거나 불완전한 답변을 허용해 2초를 달성했다고 보고하지 않는다. 캐시 적중, 일정 직행, 일반 cold 검색도 각각 구분한다.
